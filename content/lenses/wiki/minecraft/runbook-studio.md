Bringing a broadcast studio up is this runbook's subject, and it separates itself from a sibling document: this page is how to turn it on, the manual is how to operate a show.

Two banners sit at the top and both correct the body below them. The first is a correction naming which machine is now the production mixer rather than a rehearsal preview. It also describes a boot flow that is now hidden: everything starts without visible windows, and a single operator surface opens once the system answers. It also records that a crash dialog is suppressed before each launch and by a watcher that dismisses dialogs. The second banner marks the whole page as an interim system for development use, and names a document that overrides it on any conflict.

The practical core is a start sequence. One command brings the whole stack up in order, gated on health checks and safe to run again, and the order it starts things in is listed. Variants show the current state or add supervision. A manual sequence follows for when the single command is not wanted, with a warning about a command name a shell would otherwise read as something else.

A long catalogue describes the scenes, grouped by kind of show, with one singled out because it belongs to no group and can only be reached by putting it on air. Sections on overlays and audio follow.

The command centre is described as the primary control surface, with the address to open and what it offers. Further sections cover connecting cameras and microphones from another computer with nothing to install, and the idea of camera roles: a scene names a position rather than a device, so assigning a camera to a role updates every scene that uses it at once.

A text console is offered as a fallback and for scripting, and a restreamer section explains how one encode is sent onward to two platforms.

Two sections are about honesty rather than mechanics, and they give the page its character. Overlay text describes behaviour and learning only, and the science record at the time of writing is quoted with two results that are partial and provisional, with an instruction to check the current state before strengthening anything said on air. Text destined for the screen is linted against a list of forbidden words. There is a way to force a phrase past the check, which the page says means you own the claim, and it must have a committed receipt recording what was run.

The autonomy limit follows: the show runs itself inside a session the operator opened, but the outward cut is typed by the human every time, and the agent never holds a key nor approves going live for itself.

The page ends on shutdown, and that is now the longest correction it carries. An earlier version named a command that would not have stopped the outward broadcast, and the one that does was measured printing success while both pushers were still running. Two reasons are given: the success line prints whether or not the kill matched anything, and three separate things bring the pushers back within seconds. A corrected order follows: sign off while still on air, cut to standby and hold, stop the supervisors, stop the pushers, verify by counting processes rather than trusting any printed verdict, and stop the stream last. The page names the fault as one it keeps meeting: a signal that measures whether a thing exists rather than what the audience is receiving.
