The careful part is the control: a second version with the same number of moving parts, but with its halves matched. <!--CLEAR-->
Nothing here is a measurement. It is a pre-registration for a planned comparison, written down before the run so that the outcome cannot be reinterpreted afterwards, and the verdict is withheld.

The design is a three-way race. There is a baseline. There is a version whose two halves are deliberately made unlike each other. And there is a control version with the same number of moving parts as that one, but with its halves matched. Each is run for a fixed span in the same kind of environment, and two things are recorded: how widely it wanders, and how quickly it reaches a later stage.

The pass condition is that the lopsided version beats the baseline while the matched control does not. The stated way of showing it wrong is the confound. If the control shows the same advantage, then the extra parts were the cause rather than the arrangement, and the page commits in advance to calling that a failure. A middle verdict is allowed for the case where both improve but one improves more. A separate failure is recorded if an unrelated default behaviour stops being byte-identical.
