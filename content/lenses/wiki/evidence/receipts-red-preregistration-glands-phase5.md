A promise made before an experiment, and not a report of one. It sets out a test of a proposed part of a system that would nudge behaviour according to an internal state, something like being fed or being hungry. The authors name the danger themselves: this is exactly the place where a hidden reward signal could be smuggled in, and they do not want one. So the test is written to catch that. <!--CLEAR-->
Written as a pre-registration, so nothing on it has been run. It describes an organ that had not yet been built, and the checks that would have to pass before it could be. The verdict is withheld.

The header names the gate, the phase, the date it was registered, the script that would run it, and the related notes. The short motivation paragraph is the honest heart of the page: the proposed organ biases choice according to an internal state, and the authors say straight out that this is the classic place a reward signal can be smuggled into a system that is not supposed to have one.

So the pass condition has three parts. The organ must do something observable, a stated signature over a stated window. An invariance test must still pass with the organ present, which is the part that would catch a hidden per-action reward. And a default genome must stay byte-identical with the organ absent. Any one of those failing is a failure. A closing rule forbids touching the related code at all until this test passes and a review agrees.
