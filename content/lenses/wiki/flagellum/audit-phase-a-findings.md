This is the first stage of an independent audit, written to be argued with. It says so on its
first page: predictions were committed before the work ran, and the auditor's own mistakes are
listed near the end rather than quietly fixed.

The auditor ran every required check on a genuinely clean copy, fetched the outside evidence the
project cites, and hashed it all independently. Most of it holds up. The published files really
are what the project says they are, the raw data really does turn into the derived data, and the
project's most awkward self-criticism survives being redone in a different language.

The trouble is elsewhere. The identity of one frozen result depends on which version of the
runtime produced it, so on the version the project declares as its floor it cannot reproduce its
own evidence. One gate reports a pass by reading a claim rather than checking a file. One
generator quietly corrupts a pinned file in a way one common command does not show.

The auditor's summary: the claims are substantially true, and the gates that assert them
frequently do not test them.

<!--CLEAR-->

The document records the empirical baseline stage of an audit. Later stages had not started when
it was written, and it says so.

The method section is careful about isolation. The primary copy was never written to; all work
happened in separate clones, and the primary was checked byte by byte before and after with two
independent hashing tools that agreed. The environment is recorded down to tool versions.

Then a list of every required command with its result. Most pass. One passes on the newer
runtime and fails on the declared minimum. The dependency audit separates production from
development risk, reporting no production vulnerabilities alongside a set of development-only
ones. A crossed matrix shows the failure depends only on the runtime axis. A short section
corrects the test count, and notes that because the commands are chained, an early failure means
one later test never runs at all — which is not the same as passing.

The adverse findings follow. The first is that a frozen report's identity changes with the
runtime version, even when protocol, data and code identities are held constant, so the stated
condition for reproducibility is incomplete. The auditor states the magnitude plainly rather
than over-reading it: the divergence is in the last digits of a bootstrap interval, no scientific
conclusion moves, the ordering of the models is unchanged. The auditor's own hypothesis about
the cause is then refuted by a probe, and the true cause is recorded as not yet localized.

The second is that a source-integrity gate computes its result from claims written inside the
very file it is supposed to validate, and never touches the filesystem. This is demonstrated
rather than merely read: adding many megabytes of genuine, independently verified evidence
changed the generated report by zero bytes. The auditor also notes that the honest status is
currently unrepresentable, because no not-run or external-validation-required value exists
anywhere in the project's vocabulary.

The third is a line-ending trap. One generator copies a file across a boundary where the two
paths declare different line endings, so the copy changes on disk while the normalized version
stays identical. One inspection command reports nothing at all, and a developer looking at it
would reasonably dismiss the change. A test already fails correctly on it.

The positive findings are earned by measurement, not assumed. Every upstream artifact was
retrieved from its published address and hashed, and all match the declared pins — the first
time those assertions had ever been checked against real bytes. A very large archive was
retrieved and its committed verification list regenerated byte-identically. The raw-to-derived
ingestion reproduces exactly. The sample-size accounting is sound. And the adverse result the
project keeps about itself — a plain baseline out-scoring its own model — is reproduced by an
independent implementation in another language.

A short section adds nuance about the designated independent checker: some of its printed output
is hard-coded, while the assertions underneath are real and would throw. One assertion inside it
is true for every finite number and therefore tests nothing.

Then refutations, including of the auditor's own earlier claims, each with what actually
happened. A resonance table scores seven axes before and after, and two of them move downward
because the audit found something. The thesis is stated in one line: the claims are
substantially true, and the gates that assert them frequently do not test them.

The document ends by listing what was explicitly not done, giving commands to reproduce each
finding, and putting a numbered set of open decisions to whoever reviews it.
