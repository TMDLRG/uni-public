A remediation phase still in execution keeps its register here. Its status line and its counts are generated from the plan file rather than written by hand, and the reason is recorded below them: an earlier version of this line stated a status the other surfaces did not, breaching the plan's own law that none of the three may state a status the others do not — and it breached the same law again within a day. Generating the counts is described as what that law was always asking for and never had a mechanism to enforce.

A short paragraph then lists steps executed without ever gaining a row in the pre-registration table, recorded here rather than left looking like inventions. One was a necessary repair ruled on by the operator; the rest ran under the same standing authorisation. The page notes that one step's own falsifier is a step invented during execution, so that falsifier had read as fired and unanswered until this paragraph answered it, and adds that recording them late is better than not recording them at all.

The section on why the phase exists is unusually direct. The author had recommended leaving the governing body half-built in order to go and do the science; the operator rejected that as a fatal error, and the page says he was right, because it would leave the science ungoverned. Measurement then dissolved the choice, because the path to broadcast turned out to be blocked on a science gate. The road runs through the science.

The four-proof cycle is the heart of the page and binds every step. First, a test that fails first, for the pre-registered reason, matched against the actual error, then the smallest fix; any test passing early is named, and vacuous ones are marked as not counted. Second, re-measure — not the same test again, but the instrument re-run from a clean copy and compared against the baseline, with the warning that an unexpected second improvement is as suspicious as a failure. Third, a different method, named before execution, which must not import the code under test and must run against the repaired function, because one earlier repair was itself the defect; if it disagrees with the first proof, it wins, and the disagreement is spoken first. Fourth, the operator proves it himself with one command or one look, never a procedure.

A table then names, for every step, which independent method and which operator-facing form will be used, together with the falsifier. The methods range from mutation and independent reimplementation to a live probe, an adversarial agent, a historical replay, a negative control, and the operator's own eye.

The results of the first stage are then given, and the main finding is worth reading. A single response carried two mutually exclusive statements: a field claimed to report the commit the running code sits on, while it actually read the repository's head at request time. So the field that should have caught a long blind spot is the field that hid it. A table shows several long-lived processes serving code well behind the current head, including the supervisors themselves.

A retraction follows, settled by measurement: the author had reported that a check reported failure but exited successfully, and that was false — he had read the exit status of a command it was piped into. The real defect is different and stands: nothing invokes that check.

The page closes with numbered stop conditions and an exit condition requiring the next plan to exist.
