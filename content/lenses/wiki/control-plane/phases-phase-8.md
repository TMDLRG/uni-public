Nothing in this plan has been executed. The status line says pre-registered — written down in advance — and not executed, which means everything in it describes intended work rather than results.

It is the first phase aimed at the flagellum repository, which this programme had not previously touched, plus two written limits the previous phase showed were missing.

The opening section says what the previous phase changed here; each item is a lesson learned the hard way. A fix can be worse than the defect it closes: one repair had collapsed a distinction and was mandated by its own test. So every repair here gets an adversarial pass over the repaired function, not only over the original defect. A guard can be reached around, so every written limit here must name what can walk around it. A signal filed as structural stops being read, and one such signal had been pointing unread at a real problem. And the outside witness is compromised, so nothing in this phase may claim outside corroboration until the writer's key is removed.

The table names each item with its expected outcome and what would show it wrong. Before any edit, the target repository's baseline must be captured — honestly green or honestly red — because work must not land on an unmeasured tree. Then the specific defects. A pairing of scores and identifiers that truncates silently must raise before any average. A fit whose termination was unsuccessful must halt before scoring and write no artifact. An off-by-one index in a published ladder must be corrected as a new file with a new fingerprint, rather than by editing the frozen one. An over-long run must be flagged rather than silently treated as eligible. And a release check must report unverified rather than pass when an archive cannot be opened.

Two items are unusual and worth noticing. One requires a repository-wide address limit to land failing, on the stated reasoning that a green result there would mean the walk is wrong. Another requires each repaired comparison to be shown to still bite by pointing it at a bad value, because a comparison repaired without that check is indistinguishable from one loosened. A third insists that a document be corrected only after the code it describes is true, because correcting the document first closes the only signal telling the truth.

A table names each test before it is written, and adds a new procedural rule. The working-tree status goes inside every receipt — the file recording what was run — added after a receipt turned out not to be reproducible from its own commit. The standing procedure, now five phases old, ends with the newest part — a fix is adversarially reviewed as its own subject.

The section on what must not go wrong is the heart of it. The target repository holds frozen evidence with a fingerprint baseline, and any difference from it is a contract violation and a hard stop. Every guard in this phase sits beside code that produced frozen results, and the temptation is to re-run the corrected pipeline and replace the artifact. The plan says not to: a correction is a new sidecar with a new fingerprint, and the original stands, wrong, with its correction recorded next to it.

Verification lists the commands, including one expected to exit non-zero and be reported as blocked, not as a pass. Acceptance requires the frozen baseline to be byte-identical. The exit condition, as in every phase here, requires the next plan to exist before this one can close.
