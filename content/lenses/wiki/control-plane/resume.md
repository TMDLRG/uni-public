A resume point is the file a person or agent reads to find out where the work stands, what happens next, and what is still open. It begins by saying it is corrected whenever it becomes false, because a resume point that lies is worse than none, and that it had been false in every material clause for a period recorded at the end.

Its first section names the next act, and is generated from the plan rather than typed. The page is explicit that the plan file is the source of truth and this page is not, that a checker holds the plan to its own vocabulary because it had once carried two different next acts at once, and that this section once declared the wrong next act for hours after the work had shipped.

A table shows where each stage stands: several done, one blocked on the operator, one in progress and waiting on a check only a person can perform, and the last two planned. One stage is deliberately last, with the reason given — editing a document to match a broken world closes the only signal telling the truth.

The measured-state section is a series of generated blocks, each carrying a note about the error it exists to prevent. The gate counts are stated in two forms because both had been written before without saying which was which. The ledger tally is given per name and says so, because a count whose derivation is unstated is how a backlog and its history came to be reported as one word.

Then comes a block that answers nothing and lists commands instead. Three things are deliberately not stated here, because no committed file can hold them honestly: they are facts about a run or about now, not about the tree. The page says this section used to answer all three, and that one answer was false again within minutes while committed as though it were present tense.

Three checks are reported red, each reason measured rather than inherited. One is red on purpose, because its acceptance criterion asks it to find things and a green result there would mean the walk is broken. One fails on a name that does not resolve, and the page records that its own description had been half wrong until recently, because the check was failing twice and the second failure had been authored by an agent writing a fixture. One fails on a digest that no longer matches a pin, and advancing that pin is the operator's decision. The lesson drawn is that two of the three had been described by inherited prose, one of them understating a real defect.

A section headed as what must not be softened lists the standing adverse facts: the outside witness is compromised and the anchor is tamper-evident rather than unforgeable; every registered gate has no rows in the canonical ledger though the schema says it must; no verdict has yet been authored about a real scientific claim; and a guard binds this codebase's paths, not the machine.

A further section lists what is open and belongs to the operator alone: a proposed contract not yet adopted, a component that does not exist so an airlock has no door, and a set named by a count with no members.

The final section keeps everything the file used to say while it was false, clause by clause, and explains why: this file has no gate, so it drifts silently, and the only defence is a reader who checks the numbers against the world first.
